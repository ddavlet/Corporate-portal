# Дивиденды: правила выплат (перенос из n8n «New Payed Request»)

Дата: 2026-11-07. Статус: утверждено владельцем.

## Зачем

Сейчас выплату инвестиций (`InvestReturn`) по оплаченной заявке на дивиденды создаёт n8n через
`/api/n8n/investments/returns/portal-create/`. Узлы дивидендов в n8n уже выключены у всех тенантов. В n8n
у каждого тенанта своя логика: у Lemon-тенантов решает назначение платежа, у Qulay и KP — список фамилий
(`INVESTOR_VENDORS`), у Neuron — всегда «инвестор». Список фамилий — костыль, от него отказываемся.

## Правило

В настройках тенанта есть список правил «назначение платежа → тип выплаты + получатель».
Когда заявка переходит в PAYED и её `payment_purpose` совпадает с активным правилом (без учёта регистра
и пробелов по краям), портал создаёт `InvestReturn`:

- `type` и `recipient` берутся из правила;
- `sum` = `request.amount`, `currency` = `request.currency` (допустимы только USD/UZS — иначе ошибка);
- `date` = дата оплаты (`request.payed_at`, формат YYYYMMDD; если пусто — сегодня по Ташкенту);
- `billing_date` = `request.billing_date` (сериализатор приводит к первому числу месяца);
- `comment` = `Получатель: {vendor} (заявка #{id})`;
- `created_by` = системный пользователь pk=1;
- затем та же цепочка согласования, что у `portal-create`: `create_approvals_for_invest_return` в транзакции,
  `route_invest_return_approvals` в `on_commit`.

Способ оплаты (перечисление, наличные, «Инвест. …») не важен — только назначение. Нет правила — ничего не
создаётся. Фамилия получателя нигде не учитывается.

Повторная оплата / повторный вызов хука не создаёт вторую выплату: заявка связывается с выплатой один раз
(`DividendPayoutLink`, OneToOne на заявку). Ошибка создания (нет курса ЦБ, тип запрещён в форме инвестиций,
валюта не USD/UZS) не ломает оплату заявки: пишется в `DividendPayoutLink.status=FAILED` + `error` и в лог.

## Начальная настройка (data-миграция)

| Тенант | Назначение | Тип | Получатель |
|---|---|---|---|
| lemonfit, lemonaqua, lemonhavo, lemonnew | Дивиденды учредителю | тело_инвестиций | инвестор |
| то же | Дивиденды партнерам | тело_инвестиций | партнер |
| neuron | Дивиденды | тело_инвестиций | инвестор |
| qulay | Дивиденды учредителю | дивиденды | инвестор |
| qulay | Дивиденды партнерам | дивиденды | партнер |
| kp | Дивиденды | дивиденды | инвестор |

Правила создаются активными. Наличные дивиденды Lemon-тенантов («Дивиденды», «Выплата инвестиций» на
наличных) правил не получают — как и в n8n; при необходимости добавляются вручную.

Форма заявки меняется только у Qulay: у всех способов оплаты, где есть активное назначение «Дивиденды»
(сейчас «Перечисление» и «Наличные»), добавляются «Дивиденды учредителю» и «Дивиденды партнерам» с той же
категорией, а «Дивиденды» деактивируется (не удаляется). Миграция идемпотентна (get_or_create), обратная — noop.

## Модуль

Новый модуль `backend_v2/apps/modules/dividend_payouts/` (OCP: investments и requests не правим).

- `DividendPayoutRule(tenant FK, payment_purpose str(200), return_type choices InvestReturn.ReturnType,
  recipient choices InvestReturn.Recipient, is_active bool, created_at, updated_at)`;
  уникальность по (tenant, Lower(payment_purpose)).
- `DividendPayoutLink(request OneToOne, invest_return FK SET_NULL null, rule FK SET_NULL null,
  status CREATED|FAILED, error text, created_at)`.
- Хук `on_request_payed` регистрируется в `apps.py` через `register_request_payed_event_handler`.
- API (`/api/dividend-payouts/rules/`, `IsTenantAdminOrDirector`): GET список, POST создать,
  PATCH/DELETE `<id>/` — удаление правила допустимо (это настройка, не данные учёта; ссылки в Link — SET_NULL).
  Валидация: тип разрешён в `InvestmentFormConfig.allowed_return_types` тенанта (если список не пуст),
  назначение не пустое и уникально без учёта регистра.
- Admin: правила и ссылки (ссылки read-only).

## Frontend

`frontend_v2/src/lib/dividendPayoutsApi.ts`, страница `ui/settings/DividendPayoutRulesPage.tsx`, маршрут
`settings/dividend-payout-rules`, плитка «Дивиденды: правила выплат» в группе инвестиций, доступ как у
настроек инвестиций. Таблица правил: назначение (AutoComplete из активных назначений формы заявок тенанта,
можно ввести вручную), тип (только разрешённые в форме инвестиций), получатель, активность, удалить; кнопка
«Добавить правило». Если модуль недоступен (404) — понятная заглушка.
