# Еженедельный отчёт для инвесторов в Telegram

Переносит из n8n в портал отчёт для инвесторов. Сейчас его отправляют два workflow:
- старый «Investments report» (`adRG79qvDpxwYQyX`): ~100 узлов, ветки AQUA, ONE и HAVO;
- черновик «Отчёт для инвесторов — все тенанты» (`invReportAllTnt1`): 5 узлов, логика в одном Code-узле.

Формат и формулы берутся из черновика, их согласовали 26.10.2026. После переноса оба workflow выключаются.

## Цель

1. Раз в неделю (по умолчанию в понедельник в 10:00 по Ташкенту) портал отправляет каждому подключённому тенанту отчёт в **его** Telegram-группу.
2. Отправка идёт ботом этого тенанта.
3. Цифры считаются в портале по `ProjectInvestment`, `InvestReturn` и `CbuExchangeRate`, без n8n.
4. Тенант сам настраивает отчёт: включение, группу, день и час отправки, целевую доходность и месяц начала расчёта.
5. Перед включением можно посмотреть отчёт на любую дату и отправить пробный отчёт себе в личку.

## Решения

| Вопрос | Решение |
|---|---|
| Где живёт код | Модуль `investments`, новые файлы `investor_report.py` (расчёт), `investor_report_formatter.py` (текст), `investor_report_jobs.py` (расписание/отправка). Модуль `reports` не трогаем: отчёт про инвестиции и гейтится ключом `investments` |
| Куда отправлять | `TenantTelegramChat` из настройки тенанта. Групп «на всех» нет: у каждого тенанта своя |
| Каким ботом | Ботом тенанта через `TelegramDispatcher(tenant)`, как остальные исходящие сообщения. Значит, бот тенанта должен быть участником группы |
| Целевая доходность | Хранится в настройке тенанта (`target_annual_rate`, % годовых). Пусто — блоки «Целевая», «Отставание» и «По плану» не выводятся |
| Начало расчёта | `start_month` в настройке. Пусто — месяц после первой подтверждённой инвестиции текущего года, иначе январь |
| Курс | Курс ЦБ на дату операции; если на эту дату курса нет — ближайший **предыдущий** из архива; если операция раньше архива — самый ранний курс архива. Сетевых запросов к cbu.uz при построении отчёта нет |
| Права на настройки | `IsTenantAdminOrDirector` (как `cash_withdrawals`) |
| Расписание | Cron каждый час + фильтр по дню недели и часу тенанта (шаблон `run_cash_withdrawal_alerts`) |
| Защита от дублей | Журнал `InvestReportDispatch`, уникальный по (тенант, дата отчёта) |
| История | Сообщение пишется в `TelegramMessage`/`TelegramMessageHistory` диспетчером; журнал ссылается на `TelegramMessage` |

## Метрики (как в черновике n8n)

Обозначения: `today` — текущая дата по Ташкенту, `Y` — её год, `M` — месяц, `last_month = M − 1` (последний завершённый месяц года; в январе равен 0).

Учитываются только выплаты с `recipient = инвестор`, выплаты партнёрам исключены. Тип «тело инвестиций» входит в доходность, как в старом отчёте. Суммы в UZS переводятся в USD по курсу на `date` строки (см. «Курс»).

| Метрика | Формула |
|---|---|
| Вложено всего | Σ USD подтверждённых `ProjectInvestment` |
| Вложено на согласовании | Σ USD неподтверждённых `ProjectInvestment` |
| Выплачено всего | Σ USD подтверждённых выплат инвестору (за всё время) |
| Выплачено на согласовании | Σ USD неподтверждённых выплат инвестору |
| Выплачено за год | То же, `billing_date` в году `Y` |
| Период расчёта | `start_month … last_month`, `months = last_month − start_month + 1` |
| Выплачено за период | Σ USD подтверждённых выплат инвестору с `billing_date` в году `Y` и месяцем в периоде |
| Доходность, % годовых | `paid_period / months × 12 / invested × 100`; в месяц — то же `/ 12` |
| Доходность без прошлого месяца | Только если `day(today) ≤ late_payment_day`, `months > 1`, за `last_month` выплат 0, а за период > 0. Считается по `start_month … last_month − 1` |
| Целевая, % годовых | `target_annual_rate`; в месяц — `/ 12` |
| Отставание / опережение | `доходность − целевая`, в п.п. годовых и в месяц |
| Должно быть выплачено | `invested × target / 100 / 12 × months` |
| Дефицит / сверх плана | `план − paid_period`; если округлённо > 0 — дефицит, иначе «сверх плана». В скобках — выплаты на согласовании |
| Последние выплаты | `last_payouts_count` подтверждённых выплат инвестору, по убыванию `date`, при равенстве — по убыванию `billing_date` |

Крайние случаи:
- `invested = 0` → блок доходности не выводится (только «Вложено» и «Выплачено»).
- `months ≤ 0` при `invested > 0` → строка «📈 Доходность: в {Y} году ещё нет завершённых месяцев для расчёта».
- Нет выплат → блок «Последние выплаты» не выводится.
- Деление на ноль невозможно: доходность считается только при `invested > 0` и `months > 0`.

Расчёт — чистая функция `build_investor_report(tenant, today, config) -> InvestorReport` (dataclass с полями выше, суммы `Decimal`). Форматтер получает только этот dataclass. Так метрики тестируются отдельно от текста и могут понадобиться потом в API/UI.

## Текст сообщения (HTML, `investor_report_formatter.py`)

```
📊 <b>{название тенанта}</b> · {дд.мм.гггг}

💰 Вложено всего: <b>{X} $</b>[ (+{Y} $ на согласовании)]
💵 Выплачено всего: <b>{X} $</b>[ (+{Y} $ на согласовании)]
      за {Y} год: {X} $

📈 Доходность сейчас: {a}% в мес. · <b>{b}% годовых</b>
[      без учёта {месяца}: {a}% в мес. · <b>{b}% годовых</b>]
[🎯 Целевая: {a}% в мес. · <b>{b}% годовых</b>
⚠️ Отставание | ✅ Опережение: {±a} п.п. в мес. · <b>{±b} п.п. годовых</b>

📅 <b>По плану на сегодня</b> ({месяц}–{месяц}):
Должно быть выплачено: {X} $
Выплачено: {X} $
🔻 Дефицит: <b>{X} $</b> | 🟢 Сверх плана: <b>{X} $</b>[ (+{Y} $ на согласовании)]]

🧾 <b>Последние выплаты:</b>
{дд.мм} — {X} $ · {тип} за {месяц}[ {год, если не текущий}]
```

Форматирование:
- Суммы округляются до целых долларов. Разряды отделяются неразрывным пробелом.
- Проценты: в месяц — 2 знака, годовых — 1 знак, десятичная запятая. Минус — знак «−».
- Название тенанта экранируется (`html.escape`).
- Типы выплат: `доля_прибыли` → «доля прибыли», `тело_инвестиций` → «тело инвестиций».
- Отступ под строкой — 6 неразрывных пробелов, как в черновике.

Эталон — тексты, которые черновик n8n собирает на одну и ту же дату. Расхождение хотя бы в одном символе считается ошибкой переноса (см. «Переход с n8n»).

## Поток

### 1. Плановая отправка (cron)

`crontab`: `0 * * * * root cd /app && python manage.py run_invest_reports >> /proc/1/fd/1 2>&1`

`run_invest_reports [--now=ISO] [--tenant=<subdomain>] [--dry-run]`:
1. `local_now = timezone.localtime(now)` (Asia/Tashkent), `today = local_now.date()`.
2. Конфиги: `is_active=True`, `tenant.is_active=True`, модуль `investments` включён (`TenantModuleConfig`), `weekday == local_now.weekday()`, `send_hour == local_now.hour`.
3. Если по `(tenant, today)` уже есть `scheduled`/`sent` — пропуск.
4. `build_investor_report` → `format_investor_report` → `TelegramDispatcher(tenant).send(action=<send_action тенанта>, recipient_id=chat.chat_id, text=…)`.
5. Запись `InvestReportDispatch`. Если диспетчер вернул `None` — `status=failed`, `logger.error`. В следующий час повторной попытки нет: окно отправки — один час. Ручная отправка доступна из UI.
6. Каждый тенант обрабатывается в своём `try/except` с `logger.exception`: ошибка одного тенанта не останавливает остальных.

С `--dry-run` команда печатает тексты и ничего не отправляет и не пишет. Так на проде можно сверить отчёт с n8n.

Команду добавить в `_NO_POLLER_COMMANDS` (`investments/apps.py`).

### 2. Предпросмотр

`GET /api/investments/report/preview/?date=YYYY-MM-DD` возвращает `{ "text": "<html>", "metrics": {…} }`. По умолчанию берётся сегодняшняя дата. Текущие (несохранённые) значения настроек можно передать в query: `target_annual_rate`, `start_month`, `last_payouts_count`, `late_payment_day`. Так на странице настроек видно результат до сохранения.

Дата влияет на `today` (период, правило 25-го числа, заголовок). Данные берутся текущие, без отката на состояние базы на ту дату.

### 3. Ручная и тестовая отправка

- `POST /api/investments/report/send-test/` — пробный отчёт текущему пользователю в личку (`user.telegram_chat_id`). Если Telegram не привязан, возвращается 400 с понятным текстом. Журнал: `kind=test`.
- `POST /api/investments/report/send-now/` — внеплановая отправка в группу тенанта. Журнал: `kind=manual`. Плановую отправку этого дня она не блокирует.

## Переход с n8n

1. Деплой и миграция.
2. В портале по каждому тенанту выбрать группу. Проверить, что бот тенанта добавлен в эту группу (тестовая отправка в группу допустима только с согласия владельца группы).
3. Настроить:
   - `lemonaqua`: цель 34,72;
   - `lemonfit`: цель 21,4, `start_month = 2`;
   - `lemonhavo`: без цели.
   Включение пока не трогать.
4. Сверка: `run_invest_reports --dry-run --now=<дата>` против `n8n execute --id=invReportAllTnt1` на ту же дату. Тексты должны совпасть посимвольно.
5. «Отправить мне» по каждому тенанту и проверить вид в Telegram.
6. Включить конфиги в портале и **в тот же день до 10:00** выключить в n8n `Investments report` и `invReportAllTnt1`, чтобы не было дублей.
7. Первый понедельник проверить по журналу отправок.

## Ошибки и крайние случаи

| Случай | Поведение |
|---|---|
| Модуль/тенант выключен, конфиг неактивен | Ничего |
| Группа не выбрана или неактивна | Конфиг нельзя включить; если чат деактивировали после включения — `failed` в журнале, `logger.error` |
| Бот не в группе / gateway ошибка | Диспетчер вернул `None` → `failed` с текстом ошибки из `TelegramMessageHistory` |
| Нет курса ЦБ вообще (пустой архив) | Отчёт не строится, `logger.error`, `failed` |
| Строка в валюте, отличной от UZS/USD | Считается как USD (текущее поведение `usd_uzs_equivalents`), `logger.warning` |
| Два запуска cron в один час | Частичный уникальный индекс → второй получит `IntegrityError`, ловим и пропускаем |
| Январь | `months = 0` → строка «ещё нет завершённых месяцев» |
| Текст > 4096 символов | Не ожидается (≈ 900 символов); при превышении `logger.error` и обрезка блока «Последние выплаты» |

## Тесты

Backend (`investments/test_investor_report.py`):
- Расчёт по фикстурам: только инвестиции, только выплаты, ноль всего, UZS + USD, выплаты партнёрам не учитываются, неподтверждённые попадают только в «на согласовании».
- Курс: точная дата, ближайший предыдущий, раньше архива — первый курс.
- `start_month` из настройки и по умолчанию (после первой инвестиции года, иначе январь).
- Правило «без учёта прошлого месяца»: 25-го — есть, 26-го — нет; при `months = 1` — нет; при выплате за прошлый месяц — нет.
- Дефицит / сверх плана, «на согласовании» в скобках.
- Последние выплаты: порядок, лимит, год у прошлогодних.
- Форматтер: эталонный текст на фиксированную дату. Эталоны снять с черновика n8n для AQUA и ONE: на 23.10.2026 (строка «без учёта» есть) и на 26.10.2026 (её нет).
- Команда: не тот день/час — тишина; нужный — одна отправка и запись `sent`; повторный запуск — без дубля; ошибка диспетчера — `failed`; выключенный модуль — тишина; `--dry-run` ничего не пишет.
- API: права (`IsTenantAdminOrDirector` на config/send-now), чужая группа → 400, включение без группы → 400, preview с параметрами из query, send-test без Telegram → 400.

Frontend (Vitest): форма из API, сохранение payload, предпросмотр перерисовывается при смене параметров, заглушка при 403/404, подтверждение перед «Отправить в группу сейчас».

## Замечено по соседнему коду (вне рамок, отдельные PR)

Уведомления о выплатах по графику (`run_invest_notifications`):
1. Отправляются через `post_messaging_gateway` в обход `TelegramDispatcher`, поэтому в `TelegramMessage` и историю они не попадают.
2. Cron запускает их раз в день в 09:00, а фильтр стоит по `notify_hour`. Тенанты с другим часом уведомлений не получают.
3. `today = now_dt.date()` берёт дату по UTC, а не по Ташкенту.
4. `telegram_chat_id` в `InvestNotificationConfigSerializer` не проверяется на принадлежность тенанту, и сохранять настройки может любой пользователь модуля.

## Вне рамок

- Отчёт в PDF/картинкой, графики.
- Разные получатели внутри одного тенанта (несколько групп, личные рассылки инвесторам).
- Отчёт по компаниям-инвесторам по отдельности (`InvestCompany`).
- Хранение исторических срезов отчёта кроме текстового снимка в журнале.
- Исправление уведомлений по графику выплат (см. выше).
